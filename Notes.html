AWS SAP-C02 Certification Study Guide

1️⃣ Cross-Account Access (S3, ECR, APIs, Auditors, CI/CD)

Core AWS Rule

The account that OWNS the resource controls access

AWS-Preferred Patterns

Cross-account IAM roles (AssumeRole) for:
  • Auditors
  • CI/CD pipelines
  • Secure admin access
Resource-based policies when supported:
  • S3 bucket policy
  • ECR repository policy
  • SNS topic policy

Exam Signals

  • "external auditor"
  • "no long-lived credentials"
  • "secure cross-account access"
  • "least operational overhead"

Instant Answer

👉 IAM role assumption (often with external ID)
👉 Resource policy > role when available

Traps

❌ IAM users
❌ Secrets Manager for cross-account access
❌ AWS RAM for identities (RAM ≠ IAM)

2️⃣ Prevent vs Detect vs Recover (Security & Governance)

Control Hierarchy (MEMORIZE)

Goal AWS Tool
Prevent SCP / IAM policy
Detect AWS Config
Recover Native service feature

Key Patterns

  • Prevent creation → SCP
  • Detect drift → Config
  • Undo mistakes → PITR / Object Lock

Exam Signals

  • "ensure"
  • "enforce"
  • "must prevent"
  • "all accounts / future accounts"

Traps

❌ Config when prevention is required
❌ Security Hub for enforcement
❌ Lambda remediation when native prevention exists

3️⃣ Accidental Deletion & Data Protection

Native Safety Nets

  • DynamoDB → PITR
  • S3 immutability → Object Lock (Compliance mode)
  • EBS/RDS/EFS backups → AWS Backup

Exam Signals

  • "accidental deletion"
  • "human error"
  • "ability to recover"

Instant Answer

👉 Native recovery feature (not IAM denies)

Traps

❌ Deny Delete APIs
❌ Custom Lambda backups
❌ Manual snapshots

4️⃣ Networking: Private Access & Overlapping CIDRs

Golden Rules

  • Overlapping CIDRs → PrivateLink
  • Private subnet egress → NAT Gateway
  • Hundreds of VPCs → Transit Gateway
  • Third-party inline inspection → Gateway Load Balancer
  • Passive inspection → Traffic Mirroring

Exam Signals

  • "overlapping CIDR"
  • "private access only"
  • "no internet"
  • "third-party firewall"

Instant Answer

Overlap + private service → PrivateLink
Outbound only → NAT Gateway
Inline inspection → GWLB
Observe only → Traffic Mirroring

Traps

❌ VPC peering at scale
❌ VPN for intra-AWS traffic
❌ ALB for packet inspection

5️⃣ Hybrid Networking (On-Prem ↔ AWS at Scale)

AWS Reference Architecture

On-Prem
→ Direct Connect
→ Direct Connect Gateway
→ Transit Gateway
→ Shared across accounts

Must-Know Rules

  • Transit Gateway requires Transit VIF
  • DX Gateway does not route between TGWs
  • Cross-Region VPC traffic → TGW peering
  • Centralized egress → on-prem NAT

Traps

❌ Private VIF with TGW
❌ VPC peering for hundreds of VPCs
❌ Internet Gateway when on-prem egress is required

6️⃣ Compute Selection (Lambda vs Containers vs Batch)

Runtime Limits (EXAM GOLD)

Service Limit
Lambda 15 minutes
Fargate Hours
Batch Hours

Patterns

  • 15 min + scheduled + no code change → Fargate + EventBridge
  • VM-based Java/.NET → App2Container + ECS
  • Batch complexity only if Fargate is insufficient

Traps

❌ Lambda beyond 15 minutes
❌ Spot for guaranteed schedules
❌ Batch when Fargate works

7️⃣ Event-Driven Architectures (Fan-out & Reliability)

Canonical Fan-Out Pattern

Producer
→ SNS
→ SQS (per consumer)
→ Lambda

Why AWS Loves This

  • Decoupling
  • Guaranteed delivery
  • Independent scaling
  • Retry isolation

Exam Signals

  • "multiple consumers"
  • "no event loss"
  • "fan-out"

Traps

❌ One SQS queue with many Lambdas
❌ Direct Lambda invocation
❌ Kinesis unless streaming semantics are required

Quick Mapping (MEMORIZE)

Requirement Service

Immutable artifacts S3

Session data DynamoDB
MongoDB compatibility DocumentDB

Traps

9️⃣ Databases: HA, DR, and Global Access

Key Patterns

  • DynamoDB multi-Region active-active → Global Tables
  • Aurora cross-Region DR → Aurora Replica
  • MongoDB no code change → DocumentDB
  • Reporting = read-heavy → Read replicas

Traps

❌ DMS for steady-state DR
❌ Aurora for key-value/session data
❌ DIY replication

🔟 Security & Identity (Secrets, TLS, Auth)

Golden Rules

  • Eliminate credentials > rotate credentials
  • TLS enforced at the edge, not in code
  • Native security controls > WAF for basic needs

Key Patterns

  • RDS + Lambda + no secrets → IAM DB Authentication
  • API Gateway TLS → Custom domain TLS policy
  • Secrets only when IAM auth is unavailable

Traps

❌ Lambda checking TLS
❌ Custom authorizers for TLS
❌ Secrets Manager when IAM auth exists
